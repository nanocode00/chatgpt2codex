# Tauri 통합 새로고침 · CLI 조회 · 종료 최적화

기준: `perf/tauri-unified-refresh-and-lifecycle` / PR #103 위의 별도 Draft PR

## 변경 전 병목

- 상단 공통 새로고침이 일부 화면에서만 올바른 데이터를 갱신. 화면 안에도 유사한 새로고침 버튼이 중복.
- 대시보드·프로젝트·실행 환경 사이를 이동할 때 `manage_owned_cli("status")`, `inspect_owned_catalog()`를 계속 새로 호출.
- Catalog 조회는 작은 JSON 파일 2개를 읽기 위해 Node + 번들 SHA-256 검사를 명령마다 2회 수행.
- 프로필 상세 `profile show`도 Node 새 프로세스 시작.
- 앱 완전 종료: **서버가 아예 없는 경우에도** Node, CLI, cloudflared 번들을 전부 해시 검증한 뒤 포트 점유를 확인.
- 서버 실행 중 정상 종료는 CLI PID 및 터널 소유권 확인과 프로세스 종료 대기(100ms 폴링)가 포함.

## 변경 내용

- 상단바 새로고침 버튼 하나만 일반적인 현재 화면 갱신에 사용:
  - 대시보드: 앱 소유 상태 + 프로젝트/프로필 목록 + 로컬 Health
  - 프로젝트·실행 환경: 목록
  - 연결: 서버 + 외부 터널(실행 중이면)
  - 작업: 작업 목록
  - 진단: 상태/Health 재조회(명시적 Doctor, 로그, 잠금 조회는 별도 액션)
  - CLI: 마지막으로 성공한 **읽기 전용** 명령만 재실행. 변경 명령 자동 재실행 금지
  - 설정: 앱 소유 상태 + Windows 자동 시작 상태
- 화면 내부의 중복 일반 새로고침 버튼 제거. 개별 Doctor·잠금 확인·MCP 재시작과 같은 고유 액션은 그대로.
- 화면 이동 시 카탈로그 12초 내 재조회 생략, 중복 호출은 동일한 요청을 공유. MCP 상태는 이전 PR #103 네이티브 status 경로를 이용하고, 초기 메타데이터·모호한 소유권은 기존 검증 경로를 사용.
- 프로젝트·프로필 목록 및 프로필 상세 조회를 **고정된 격리 HOME 안의 JSON 파일**로 직접 수행. 512KiB 크기 제한, 심볼릭 링크 거부, 버전/별칭/필드/개수/경로 검증. 프로젝트 루트는 실제 디렉터리 존재 여부 확인. 민감한 프로젝트 루트는 목록 응답에서 제외. 이 경로에서 Node나 셸을 실행하지 않음.
- CLI 콘솔뿐 아니라 Diagnostics와 Profiles 등 기존 typed `runOwnedCliParity` 소비자도 같은 읽기 전용 fast path 공유. `profile test`, `repository show`, `job list` 등 실제 검사 명령과 모든 변경 명령은 CLI 경로 유지.
- **서버 중지 상태의 완전 종료**는 SHA 검증이 필요 없으므로 격리된 기록 없음 + 포트 비점유를 확인해 즉시 종료. 기록이 있으면 반드시 SHA 검증, 소유권 검증, 감사된 CLI stop 수행.
- 서버 종료시 PID 종료 확인 폴링 100→25ms, 최대 대기시간은 그대로 유지. Rust의 종료 후 포트 확인도 25ms 폴링. 잘못된 PID, 외부 포트 점유, 남은 기록은 여전히 실패 폐쇄.
- UI에서 종료 중을 명확하게 표시.

## 검증

- Windows Rust 픽스처: 격리된 JSON 목록/상세, 파일 버전 및 크기 오류, 루트 비노출.
- Windows Rust 픽스처: 실행 불가능한 Node 경로에서도 무기록·빈 포트 종료 가능, 포트 점유 시 거부, 기록 존재 시 기존 CLI 경로로 전환.
- 소스 회귀: 상단바 단일 일반 새로고침, 네이티브 status/catalog, CLI 변경 명령 재실행 금지.
- Windows CI: 일반 CI, Tauri Desktop Smoke, 원래의 PID·종료·인증 테스트 통과 필요.
- 사용자 확인:
  1. 각 화면으로 이동하며 중복 새로고침 버튼이 사라졌는지, 상단바가 현재 화면 데이터를 갱신하는지
  2. 프로젝트/실행 환경 화면 목록 및 CLI `c2c repository list`, `c2c profile list`, `c2c profile show <alias>` 실행시간
  3. CLI에서 `stop` 후 상단 새로고침을 눌러도 서버가 다시 시작하지 않는지
  4. MCP 중지 상태와 실행 상태 각각 종료 시간을 비교하고, 종료 후 포트가 풀리는지

이 작업은 사용자 PC의 종전·신규 벤치마크 숫자가 없는 상태에서 만든 구조 개선이다. 속도 개선의 배수는 Windows 실측 전에는 주장하지 않는다.
