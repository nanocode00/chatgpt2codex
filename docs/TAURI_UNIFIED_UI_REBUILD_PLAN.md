# C2C Tauri 통합 앱 — UI/UX 재구성 결정문
> 확정: 2026-11-10 · 사용자 결정 사항 · 작업 상태: 설계 확정, 화면별 점진 구현
> 선행 기준: PR #94 (`feat/tauri-f5f-acceptance-batch`), `src/cli.ts`, `docs/TAURI_CLI_PARITY_MATRIX.md`.
> 이 문서는 목표 상태와 이행 계획이다. 현재 Preview 구현이 모두 완료됐다는 의미가 아니다.

## 0. 제품 방향과 불변 조건
1. **최종 제품은 Windows WinForms 런처를 Tauri 앱으로 완전히 대체한다.** 둘을 영구 병행하는 제품은 만들지 않는다.
2. CLI는 독립적으로 계속 사용할 수 있도록 유지한다. GUI는 CLI의 안전한 사용 사례를 사용자 작업 단위로 제공한다.
3. 사용자에게 명령어를 외우게 하지 않는다. 네비게이션과 화면은 **대시보드 / 프로젝트 / 실행 환경 / 작업 / 연결·보안 / 진단·복구 / 설정 / 고급 기능** 중심으로 재구성한다.
4. 현 시점의 WinForms `default:7979`와 Tauri `tauri-preview-v1:18797`는 격리 유지. **데이터/인증/포트/터널의 검증된 이관이 완료되기 전에는 WinForms를 종료·삭제·덮어쓰기·자동 이전하지 않는다.**
5. 사용자 확인 전 변경사항을 기존 WinForms에 반영하지 않는다. Owner Token과 OAuth 승인, 비밀정보는 로그/일반 UI 상태에 노출하지 않는다.
6. 기존 PR #94는 별도 자동 테스트 및 사용자 검수 흐름을 유지한다. 이 UI 재설계는 독립된 **스택 브랜치/PR**에서 화면 단위로 진행하고 검수한다.

## 1. CLI 기능 처리 정책

| CLI 명령/범주 | 최종 GUI 정책 | 비고 |
| --- | --- | --- |
| `start/stop/restart/reload` | 일반 UI 지원 | 실제 관리 대상 인스턴스 명시, 외부 프로세스 소유권 확인 |
| `status/ps/health/logs/doctor` | 일반 UI 지원 | `ps` 별칭은 별도 메뉴를 만들지 않음; 상태/진단으로 통합 |
| `repository list/show/add/remove` | 프로젝트 지원 | 등록 해제는 파일 삭제가 아님; 실행 중 변경 지원 여부 안전성 재검토 |
| `profile list/show/add/remove/test` | 실행 환경 지원 | Python/Docker 각각 설정·검증; 현재 Docker test는 실제 실행 테스트가 아님 |
| `job list/status/logs/resume/cancel` | 작업 관리 지원 | `resume`은 상태 전환이지 에이전트 자동 재실행이 아님. `cancel`의 실제 중단 의미도 명확히 |
| `config show/set/unset/export` | 설정·고급 설정 지원 | UI 모니터링 포트와 MCP 서버 포트 엄격히 구분, 적용/재시작 안내 |
| `config import` | 설정 → 가져오기 | 파일 검증, 미리보기, 충돌/되돌리기 안전장치 필요 |
| `secret list/set/remove` | 연결·보안 지원 | 읽기 시 비밀 **이름만**; 값 입력·교체·삭제는 인증/확인 및 비노출 처리 |
| `owner-token --status/--generate/--rotate` | 연결·보안 지원 | 토큰 최초/재발급 1회 표시, 기존 OAuth 승인 무효화 고지 |
| `owner-token --set-stdin` | 고급 보안 또는 온보딩 | 기존 토큰 수동 등록이 필요한 경우에만 별도 안전 입력 경로 제공 |
| `lock list/release --force` | 진단·복구 지원 | 정상 복구 실패 시에만 경고, 잠금 소유 프로세스 확인 및 명시적 동의 |
| `control list/approve/approve-all/reject/kill` | **독립 고급 모듈** | Windows 제어 권한/구현 별도 검증; 제공 시 긴급 중지는 쉽게 접근 가능하게 |
| `control auto status/on/off` | **독립 고급 모듈** | 기본 OFF, 허용 앱/동작/시간/최대 횟수 제한 |
| `control preflight` | Windows 일반 UI 제외 | 현재 구현은 macOS 권한 검사 중심. Windows 별도 구현 전까지 지원 주장 금지 |
| `serve` | 일반 UI 직접 명령 제외 | GUI의 서버 시작 동작/내부 런타임이 대체 |
| `init` | 일반 UI 직접 명령 제외 | 최초 실행 온보딩/준비 마법사로 대체 |
| `repository use` | 일반 UI 제외 | 복수 프로젝트를 도구별 `projectId`로 지정; 전역 선택 UX 불필요 |
| `profile/config/secret import-env` | 일반 UI 제외 (CLI는 유지) | 환경 변수 기반 자동화 용도; 기본 GUI 대신 파일 입력/직접 설정으로 제공 |
| `help` | UI 도움말/상태별 가이드 | CLI 원문 help 버튼의 중복 구현은 불필요 |

**제외는 CLI의 명령을 삭제한다는 뜻이 아니다.** 고위험·자동화 용 명령을 GUI 기본 화면에 무분별하게 노출하지 않는다.

## 3. 화면별 점진 구현 규칙
1. 매 화면마다 **현상 목록 → 사용 시나리오/정보 구조 → 구현 → 자동 검증 → 사용자 수동 확인** 순서로 진행.
2. 첫 단계에서는 화면만 교체하고 서비스 수명주기, 인증, 터널, 프로젝트 저장 방식 등 고위험 백엔드 동작은 함부로 변경하지 않는다.
3. 읽기/연결/변경/외부 공개 등 동작을 구분하고 실패 상태를 숨기지 않는다. 버튼을 임의로 활성화하거나 모든 기능을 성공으로 가장하지 않는다.
4. 기존 WinForms 호환/전환 마법사, 선행 기능 및 CLI 경계는 안정적으로 유지하며, 통합 전환의 최종 승인 전에는 폐기하지 않는다.
5. 각 화면은 독립 UI 모듈로 분리하고 고정된 타입·상태를 전달한다. 기능과 표현을 분리하여 후속 화면에서 재사용한다.
6. UI 개편 PR은 최종 전환 PR과 분리한다. 기존 Windows Preview의 실행/자동 테스트/사용자 검수 결과를 보존한다.

## 4. WinForms 완전 대체 릴리스 게이트
- **마이그레이션 인벤토리:** 기존 WinForms 설치/시작프로그램, 프로젝트 목록, Python/Docker 프로필, Owner Token/OAuth, Secret, Quick/Named Tunnel, 포트, 백업 경로의 실제 지원 여부 확인.
- **백업/복구:** 버전 확인 가능한 암호화 백업과 복원 리허설. 원본 자료는 검증 전 보존.
- **이관 리허설:** 격리 환경에서 수동/자동 이관 차이를 검증. 토큰을 복구할 수 없는 경우는 재연결 절차를 명시.
- **연결 검증:** Tauri에서 로컬/공개 Health뿐 아니라 실제 ChatGPT OAuth 후 `workspace_list_projects` 등 읽기 도구 호출 성공.
- **운영 검증:** Windows 설치/업그레이드/제거, 트레이/자동 시작/종료, 절전 복구, 오류 복구, 기존 7979와 충돌 없음.
- **명시적 전환 승인 이후에만:** 이전 WinForms 자동 시작 비활성화, 설치 제거, 단일 앱 역할 전환. 실패 시 원래 환경으로 돌아갈 수 있어야 함.

## 5. 대시보드 1차 피드백 및 공통 UI 규칙 (2026-11-10)

사용자 직접 피드백 — 최종 디자인 패스는 다른 화면 재구성 후 재검토한다.

1. MCP 실행 제어는 **한 자리에서 하나의 상태별 버튼**만 표시한다: 꺼짐 → '시작', 켜짐 → '중지'. 실행 중 '재시작'은 별도 보조 동작.
2. **외부 연결 카드에 모든 공개 관련 작업을 통합**한다: 외부 공개 On/Off, Cloudflare 연결 상태, 공개 주소, 복사, 자동 HTTPS 상태. MCP 제어 카드에 '공개 연결로 시작' 버튼을 두지 않는다.
3. **서버 실행과 외부 공개 설정은 별개**로 다룬다. MCP가 꺼진 때 On/Off는 설정만 저장하고 다음 시작에 적용. 켜진 상태에서는 Cloudflare Quick Tunnel만 안전하게 붙이거나 떼며 MCP 프로세스는 유지해야 한다. URL이 바뀔 때 OAuth issuer/resource/allowlist도 동기 갱신되어야 하므로 CLI/Tauri 실행 모델 보완과 검증이 필요. 구현 전까지 작동하는 것처럼 가장하지 않는다.
4. 복사·저장·일반 성공 알림은 기존 카드 아래에 새 텍스트 영역을 삽입하지 않고 **앱 공통 토스트**로 알린다. 진행 오류/보안 주의가 장기적으로 필요한 경우에는 별도 UI를 허용.
5. **같은 카드의 주·보조 버튼 높이/패딩을 통일**하고 일관된 시각적 위계를 사용한다.
6. 외부 연결이 실제 켜져 있다면 **자동 HTTPS 상태 확인**을 시작·복귀·일정 주기에 수행한다. 수동 조회 클릭 없이 최근 확인된 값 또는 '확인 중/실패'를 표시하되 HTTPS 확인과 OAuth 성공을 혼동하지 않는다.
7. 현재 UI에 남은 초록·민트 배색을 걷어내고 **무채색/중성 포인트** 중심으로 통일한다. 온라인/오류 상태에는 제한된 의미 색상을 사용할 수 있다.
8. 데스크톱 전용 백엔드 동작에 대해서는 사용자 피드백을 이 문서에 계속 쌓고, 전체 화면 재구성 종료 시 대시보드를 다시 최종 검토한다.

### 실행 중 외부 공개 전환 백엔드 합격 기준
- 전용 Node MCP PID/포트/프로젝트 목록/세션이 외부 On/Off 전환 중 유지되고, 기존 WinForms `7979`에는 영향이 없어야 한다.
- Cloudflare 프로세스는 기존 소유권 확인 후에만 제어하며, 알 수 없는 PID는 건드리지 않는다.
- URL 갱신 시 OAuth 메타데이터 issuer, protected-resource audience, 허용 Host/Origin, 실제 ChatGPT 승인·도구 호출이 함께 검증되어야 한다.
- 실행 중 터널 재설정 실패 시 실제 상태를 읽어 표시하며, 클라이언트에 허위 성공을 응답하지 않는다.
- URL 변경 후 필요한 ChatGPT 커넥터 재등록/재승인을 명확하게 안내한다.
- Windows 단위/격리 E2E 검증 후 UI의 실시간 외부 토글을 활성화한다.


### 프로젝트 화면 구현 경계 (Draft PR #96)
- 새로운 **프로젝트** 화면은 Tauri 소유 목록에서 프로젝트 검색·상태 확인·상세 조회·폴더 등록·등록 해제까지 통합한다. 기존 관리 화면에는 화면 이동 링크만 남긴다.
- 목록은 `repository list` 기반, 세부 경로·Git 브랜치·작업 트리 상태는 선택된 ID에 대해 실제 `repository show` 읽기 전용 호출로 가져온다.
- 프로젝트 등록 경로는 OS 폴더 선택기에서 확보하고, 확인 단계에서 기존 Rust/CLI 검증을 그대로 사용한다. 임의의 웹뷰 경로 입력이나 실제 폴더 삭제는 허용하지 않는다.
- **현재 실행 중 등록·해제는 Rust에서 차단**한다. CLI는 Live Reload 가능하지만 안전하게 실시간 변경을 허용하려면 소유권/캐시/레이스 조건을 별도 시험한 뒤 제약을 풀어야 한다.
- 화면과 코드가 있다는 것만으로 완료 처리하지 않는다. 사용자의 Windows 화면 검수 및 실제 등록·조회·해제 검증이 필요하다.

### 프로젝트 화면 후속 개선 후보 — 등록 가능한 프로젝트 자동 탐색 (백로그)

**상태: 요청 접수, 아직 구현하지 않음.** 2026-11-10 사용자가 프로젝트 관리 화면을 검토하면서 제안.

- 프로젝트 화면에 **「프로젝트 찾아보기」** 기능을 추가한다. 사용자가 탐색 시작 폴더를 Windows 선택기로 고르면, 그 하위에서 프로젝트 *후보*를 탐색한다.
- C2C의 기존 `inspectProjectRoot` 규칙과 동일한 마커(`.git`, `package.json`, `Cargo.toml`, `go.mod`, `requirements.txt`, `pubspec.yaml`, `.chatgpt2codex`)를 재사용하고, 유효한 프로젝트 폴더인지 검증한 후 보여준다.
- **탐색 깊이/최대 후보 수/소요 시간 제한**, 제외 폴더(예: `node_modules`, 빌드 결과물, 시스템 디렉터리), 심볼릭 링크·정션 순환 방어, 권한 오류 건너뛰기를 갖춘다. 기본적으로 전체 디스크/사용자 홈 무차별 검색을 하지 않는다.
- 현재 등록 목록과 후보의 정규화된 경로를 비교하여 **기등록 프로젝트 중복을 제거**한다.
- 결과에는 폴더명, 경로, 탐지 근거, 접근 가능 여부를 표시하고 후보를 체크하여 기존 등록 확인 플로우로 전달한다. 자동 등록하지 않는다.
- 탐색 중 파일 내용, 비밀정보, Git 히스토리를 수집하지 않는다. 사용자 선택 전 외부 전송이나 프로젝트 변경도 하지 않는다.
- 별도 구현·테스트·Windows 사용자 검토 후 완료 처리한다.

### 프로젝트 화면 경로 접두사 표시 오류
- 사용자 검수에서 `fastdesk`, `gitday-pull`의 등록 경로 앞에 Windows 확장 경로 접두사 `\\\\?\\`가 나타남.
- 프로젝트 상세 화면 및 폴더 선택 미리보기, 경로 복사에서는 드라이브/UNC의 표준 표시 경로로 변환한다. **내부 CLI 인자·소유권/동일성 검증에는 원본 경로를 유지**한다.
- Windows 드라이브, UNC, 일반 경로, 미지원 장치 경로 회귀 테스트 추가. 실제 Windows Preview에서 재확인 필요.

### 프로젝트 화면 추가 검수 — 목록 높이 및 앱 공통 스크롤 (2026-11-10)

- 사용자 확인: **D 드라이브 프로젝트 경로는 정상 표시됨.** 확장 경로 접두사 보정은 Windows 드라이브/UNC에 대해 회귀 테스트 유지.
- 사용자 피드백: 프로젝트 4개부터 목록 높이가 계속 늘어남. **항상 3개 행의 높이로 고정**, 4개부터 목록 내부 스크롤. 선택된 프로젝트의 우측 상세 패널 높이에 따라 목록 카드가 늘어나지 않게 함.
- UI 규칙: 사이드바를 제외한 콘텐츠 너비로 반응형 처리하며, 카드·로그·전체 페이지를 포함한 앱 스크롤바는 **중성 회색 다크 테마**로 통일. 마우스/키보드 스크롤 및 고대비 환경을 유지.
- 실제 Windows 앱에서 1~3개/4개 이상, 기본 창 너비와 좁은 창 너비, 스크롤바 모양 검수를 통해 확정.

### 실행 환경 화면 (3단계, Draft PR #97) — **최종 설계 결정: 완전 분리**

- 사용자 피드백으로 결정을 변경했다. Python과 Docker는 같은 별칭으로 저장될 수 있지만 **C2C가 자동으로 묶어 실행하는 기능은 없다**. 기존 '통합 등록' 및 '복합 프로필 상세' 설계는 **폐기**한다.
- **전체 / Python / Docker 요약 카드 자체를 클릭 가능한 필터**로 사용한다. 별도의 상단 Python/Docker 탭은 제거하여 중복 탐색 요소를 없앤다. 전체 목록에서는 같은 별칭도 **(종류, 별칭)** 조합으로 별개 항목 2개를 표시하고 각 항목의 실행 환경 종류를 표기한다.
- **Python 추가 / Docker 추가 버튼은 필터와 무관하게 항상 나란히 표시**하고 동일한 기본(밝은) 색상을 사용한다. **전체 필터에서는 어느 추가 버튼을 눌러도 전체 필터를 유지**하며, 저장 완료 뒤에도 전체로 남는다. Python/Docker 전용 필터에서 반대 종류를 추가할 때만 해당 종류로 전환하고 전용 등록 폼을 연다. 폼은 선택된 종류의 입력만 표시한다. Python은 절대 경로의 `python.exe`, Docker는 Compose 상대 경로·프로젝트·서비스 설정을 받는다. 종류별 추가·수정·제거 명령만 호출한다.
- **'별칭 전체 제거' UI 및 `profile-add-both` 프리뷰 브리지**는 제거한다. CLI의 `profile add` 복합 인자 지원과 저장소 `profiles.json`의 `python`/`docker` 맵은 **그대로 유지**해 기존 프로필을 보존한다.
- `profile show`/`profile test`는 별칭을 받는 기존 CLI를 호출하지만, 화면에는 현재 선택 종류의 상세와 검증 결과만 표시한다. Python은 실행 파일 가용성 검사, Docker는 **설정 형식 확인만 제공**한다. 실제 Docker 데몬 접속이나 컨테이너 실행 성공으로 표시하지 않는다.
- 수정·제거는 선택 종류에만 적용되며, 다른 종류에 같은 이름이 있더라도 영향을 주지 않는다. 종류별 교체 확인 절차 및 수정 실패 시 목록 재조회 유지.
- 목록은 **3개 높이 고정/내부 스크롤**, 반응형 레이아웃 및 앱 공통 무채색 스크롤바·토스트를 사용한다.
- 대시보드의 실행 환경 개수는 중복 별칭 수가 아니라 **Python 개수 + Docker 개수**로 계산한다.
- `docker-smoke` 설정 테스트에서 Docker 등록이 정상 작동함을 사용자 확인. 신규 Windows 화면에서 3가지 카드 필터/항상 보이는 2개 추가 버튼/중복 별칭/독립 삭제 확인 후 고정한다. 자동 탐색 등 프로젝트 화면 기능은 별도 백로그.
- 이 변경은 PR #97에서 진행하며 **프로젝트 화면(#96)은 검수 완료 상태로 유지한다**. WinForms `7979`와 기존 인증/프로필 데이터는 변경하지 않는다.

**결정 이력:** 처음에는 별칭을 공유하는 복합 UI를 고려해 통합 입력도 구현했지만, 실제 런타임 연결이 없다는 점을 확인한 뒤 2026-11-11에 독립형 관리로 최종 변경했다. 이전 통합 UI를 다시 활성화하지 않는다.

### 작업 관리 화면 (4단계, Draft PR #98)

- **3단계 실행 환경 화면은 사용자 승인을 받아 동결했다.** 프로젝트/실행 환경 화면의 UX·기능을 이 단계에서 변경하지 않는다.
- 저장된 작업은 독립 Tauri HOME의 `goal_loop` / durable job 기록이며, **서버 프로세스나 진행 중인 에이전트 그 자체가 아니다.** 작업 ID는 `loop-...` 형식. 프로젝트 ID와 구별한다.
- 고급 CLI 화면에 흩어진 `job list/status/logs` 조작을 **작업** 전용 화면에 모은다. 목록·검색·상태 카드 필터(전체/활성/대기·차단/완료·취소), 상세 조회, 최근 기록(최대 10개)을 지원한다.
- `job resume/cancel`은 전용 Rust allowlist에서 검증된 loop ID만 허용한다. 각각 **기록 상태를 `active` / `canceled`로 변경**하며 에이전트 실행, 강제 종료, 파일 삭제를 수행하지 않는다. 해당 의미를 UI 및 확인창에 명확히 표시한다.
- 완료된 작업의 재개/취소 버튼은 UI 기본 흐름에서 비활성화하며, 가능한 상태 전이만 표시한다. 네이티브 Rust 검증이 최종 보안 경계이고 arbitrary argv, 다른 HOME/instance, WinForms 데이터 조작은 금지한다.
- CLI 반환 JSON은 ID/상태/유효한 필드만 제한해 렌더링하고, 최근 로그는 사용자가 명시적으로 요청한 뒤 표시한다. 기존 Rust 민감정보 가림 외에 브라우저에서도 길이와 토큰 형태를 제한한다.
- 목록은 3개 행 높이 고정 및 내부 스크롤, 대시보드와 같은 중성색 팔레트·공통 스크롤바 사용. 작업이 0개인 경우 정상적인 빈 목록으로 표시한다.
- 초기 실행·창 복귀·약 45초 주기 목록 상태 새로고침. 사용자 수동 확인은 빈 상태와 작업 있는 상태, 상태 전이 후 실제 CLI 조회 값 일치, 상세·로그, 구독/인증 토큰의 비노출 중심으로 진행한다.
- 실제 ChatGPT에서 작업을 이어서 실행하는 것은 **별도 도구 호출**이 필요하므로 `resume` 성공만으로 실제 에이전트 재시작을 주장하지 않는다.
